# WCAG 2.1 AA Accessibility Audit · Openclaw Architecture Explorer

## Overall verdict: **FAIL (WCAG 2.1 AA)**

The site has solid bones (`<html lang="en">`, descriptive `<title>`, proper H1, `aria-label` on icon-only buttons, `aria-hidden` on decorative SVGs, `aria-label` on search inputs, reduced-motion honored) but fails AA on five blocking issues:

1. **No keyboard focus indicator visible on the dark hero/header.** The UA default `outline: auto 1px rgb(16,16,16)` is near-invisible against `#050B1A`. Affects every keyboard user. (SC 2.4.7)
2. **`role="tablist"` containers contain plain `<button>` children with no `role="tab"`.** Three instances (`#integFilters`, `#cronFilters`, `#projFilters`). Axe critical violation. (SC 1.3.1, 4.1.2)
3. **No `<main>` landmark.** The entire page content is direct child of `<body>`, with no main region. Screen-reader skip-to-main is broken. (SC 1.3.1, 2.4.1)
4. **No skip-to-content link.** Keyboard users must Tab through ~10 header items every load. (SC 2.4.1)
5. **CRM integration-type pill: 4.15:1 contrast** at 10px text on light background. AA requires 4.5:1. (SC 1.4.3)

Plus heading-order failure (h2 then h4 in footer), missing `aria-current`/`aria-selected` on active nav and filter tabs, missing `aria-expanded`/`aria-haspopup`/`aria-controls` on the command-palette trigger, missing focus management on palette open/close (input not auto-focused; focus not returned to trigger on Esc), and 9.5px/11px caption text at 3.6 to 3.7:1 ratios.

## P0 violations (blocking WCAG 2.1 AA)

### P0-1. No visible focus indicator on dark surfaces (SC 2.4.7 Focus Visible)

**Measured:** Tabbing onto `a.brand` in the header yields `outline: rgb(16,16,16) auto 1px`. Contrast ratio of `#101010` on `#050B1A` is roughly 1.07:1, effectively invisible. Stylesheet contains **zero** `:focus` or `:focus-visible` rules across all rendered CSS.

**Affected:** every interactive element on the dark hero, header, dataflow panel, ticker, and footer. Selectors include `.brand`, `.top-nav a`, `.search-trigger`, `.icon-btn`, `.btn-primary`, `.btn-ghost`, `.cmdk-item`, palette input, and all focusable SVG nodes.

**Fix (CSS, drop into `<style>`):**
```css
:focus-visible {
  outline: 2px solid var(--mc-blue-soft);
  outline-offset: 2px;
  border-radius: 4px;
}
/* light-surface variant inside sections */
section:not(.hero) :focus-visible,
footer :focus-visible {
  outline-color: var(--finexio-blue);
}
:focus:not(:focus-visible) { outline: none; }
```

### P0-2. `role="tablist"` without `role="tab"` children (SC 1.3.1, SC 4.1.2)

**Selectors:**
- `#integFilters` (16 buttons)
- `#cronFilters` (4 buttons)
- `#projFilters` (3 buttons)

**Current markup (line 883, 905, 952):**
```html
<div class="filters" id="integFilters" role="tablist"></div>
```
Children are injected via JS as plain `<button class="filter-chip" tabindex="0">`.

**Fix, choose one:**
- **Option A (simplest, recommended):** Remove `role="tablist"` from the three filter containers. These are filter buttons, not WAI-ARIA tabs (they do not show/hide tab-panels, they filter a result list). Strip `tabindex="0"` from the buttons (they are already focusable). This kills the axe violation outright.
- **Option B (preserve tab semantics):** Add `role="tab"` and `aria-selected="true|false"` to each button, give each a unique `id`, and link to a tabpanel with `aria-controls`. Overkill for filter chips.

In the JS that builds these chips (likely a `chip.outerHTML` template), change:
```js
`<button class="filter-chip${active ? ' is-active' : ''}" tabindex="0">…</button>`
```
to:
```js
`<button class="filter-chip${active ? ' is-active' : ''}" aria-pressed="${active}">…</button>`
```
and remove `role="tablist"` from the wrapper. `aria-pressed` correctly conveys filter toggle state.

### P0-3. No `<main>` landmark (SC 1.3.1, SC 2.4.1 Bypass Blocks)

**Measured:** `document.querySelectorAll('main').length === 0`. All content sits as direct siblings of `<body>`.

**Fix (HTML):** Wrap from after `</header>` to before `<footer class="foot">` in `<main id="main-content">…</main>`.

### P0-4. No skip-to-content link (SC 2.4.1 Bypass Blocks)

**Measured:** First focusable element is `a.brand`. No `[href="#main"]` or "Skip to" link exists.

**Fix (HTML, immediately after `<body>`):**
```html
<a href="#main-content" class="skip-link">Skip to content</a>
```
**CSS:**
```css
.skip-link {
  position: absolute; top: -40px; left: 8px;
  background: var(--mc-blue); color: #fff;
  padding: 10px 14px; border-radius: 6px;
  font-weight: 600; font-size: 13px;
  z-index: 1000;
  transition: top 120ms;
}
.skip-link:focus { top: 8px; }
```

### P0-5. Insufficient color contrast on CRM pill (SC 1.4.3 Contrast Minimum)

**Measured:** `.integ-type[data-type="CRM"]` paints `#B85C00` on `#FFF1E6` for 10px regular text, which is **4.15:1**. AA requires 4.5:1.

**Selector (CSS line 399):**
```css
.integ-type[data-type="CRM"] { background: #FFF1E6; color: #B85C00; }
```
**Fix:** Darken the foreground.
```css
.integ-type[data-type="CRM"] { background: #FFF1E6; color: #9A4C00; } /* 5.16:1 */
```

### P0-6. axe-core color-contrast violation on `.label` inside `.search-trigger` (SC 1.4.3)

**Measured (axe):** `#7c838f` on `#2f3440` is **3.26:1** for the "Jump to anywhere…" label inside `.search-trigger`. Need 4.5:1 for 12.5px regular text.

My direct measurement of `.search-trigger .label` against the actual painted header background (`rgb(10,16,31)`, composite of header alpha over hero) returned **3.71:1**. Either way: fail.

**Selector (CSS line 86):**
```css
.search-trigger {
  …
  color: var(--mc-text-3);  /* rgba(230,241,251,0.42) */
  background: rgba(255,255,255,0.02);
}
```
**Fix:** Bump `.search-trigger`/`.label` color from `--mc-text-3` (42% white) to `--mc-text-2` (65% white) for 7.46:1.
```css
.search-trigger { color: var(--mc-text-2); }
```

## P1 violations (likely AA failures)

### P1-1. Heading order: h2 then h4 in footer (SC 1.3.1, SC 2.4.6 Headings)

**Selector:** `footer.foot > div.wrap > div > h4` (3 instances: "System", "Reference", "Source").

The last visible heading before footer is `<h2>` ("Six layers. One process."). The footer column heads jump straight to `<h4>`.

**Fix:** Change footer column heads from `<h4>` to `<h3>`. Lines containing `<h4>System</h4>`, `<h4>Reference</h4>`, `<h4>Source</h4>`.

### P1-2. Active nav/tab state not exposed to assistive tech (SC 1.3.1, SC 4.1.2)

**Measured:** `.is-active` class is applied to active top-nav link and active filter chips, but **no `aria-current` or `aria-selected`** attribute is set. Screen-reader users hear no difference between "Providers" (active) and "Crons" (inactive).

**Fix in JS (the scroll-spy and filter handlers):**
- Top nav: when adding `is-active` to `.top-nav a`, also set `el.setAttribute('aria-current', 'page')`. Remove it from other nav links.
- Filter chips: set `aria-pressed="true"` on active, `aria-pressed="false"` on others. This replaces the broken `role=tablist`/`aria-selected` pattern from P0-2.

### P1-3. Command palette: no `aria-expanded`, no focus management (SC 4.1.2, SC 2.4.3 Focus Order)

**Selectors:** `#cmdkOpen` (trigger), `#cmdkOverlay` (dialog).

**Measured:**
- Trigger button has no `aria-expanded`, `aria-haspopup`, or `aria-controls`.
- Opening the palette (`cmdkBtn.click()`) does **not** move focus to `#cmdkInput`. `document.activeElement` remains `<body>`.
- Closing with Esc does **not** return focus to the trigger. `document.activeElement` is `<body>`.
- No focus trap. Tab inside an open palette escapes into the underlying page (which has no `inert` and still receives focus).

**Fix:**
```html
<button class="search-trigger" id="cmdkOpen" type="button"
        aria-label="Open command palette"
        aria-haspopup="dialog"
        aria-expanded="false"
        aria-controls="cmdkOverlay">
```
In the open-palette JS:
```js
function openCmdk() {
  cmdkBtn.setAttribute('aria-expanded', 'true');
  cmdkOverlay.style.display = 'flex';
  queueMicrotask(() => document.getElementById('cmdkInput').focus());
  // trap focus: listen for Tab inside overlay
}
function closeCmdk() {
  cmdkBtn.setAttribute('aria-expanded', 'false');
  cmdkOverlay.style.display = 'none';
  cmdkBtn.focus();
}
```
Add a focus trap or use `inert` on `<main>`/`<header>`/`<footer>` while the palette is open.

### P1-4. Command-palette input has no accessible name (SC 4.1.2, SC 3.3.2 Labels or Instructions)

**Selector:** `<input id="cmdkInput" placeholder="Search sections, integrations, projects…">`

**Measured:** No `aria-label`, no `<label for>`, no `aria-labelledby`. Placeholder is not an accessible name.

**Fix:** Add `aria-label="Search the explorer"` to the input.

### P1-5. Stat label, dataflow meter, console timestamp, ticker delta-flat fail contrast (SC 1.4.3)

Four small-caption colors fail 4.5:1:

| Selector | fg/bg measured | Ratio | Required |
|---|---|---|---|
| `.hero-stats .stat-label` | `rgb(103,111,124)` on `rgb(11,17,31)` | **3.72:1** | 4.5:1 |
| `.dataflow-meter` (mc-text-3) | `rgb(101,110,126)` on `rgb(7,15,35)` | **3.70:1** | 4.5:1 |
| `.console .ts` timestamp | `rgb(98,105,114)` on `rgb(3,6,15)` | **3.64:1** | 4.5:1 |
| `.ticker-item .delta-flat` | `rgb(104,116,138)` on `rgb(12,26,56)` | **3.66:1** | 4.5:1 |

Root cause: `--mc-text-3: rgba(230,241,251,0.42)` is too transparent.

**Fix:** Raise `--mc-text-3` alpha or switch these labels to `--mc-text-2`.
```css
:root {
  --mc-text-3: rgba(230,241,251,0.58); /* about 5.0:1 on #050B1A */
}
```

## P2 issues (would fail strict review)

### P2-1. Touch target size (SC 2.5.5 AAA; informational)

44 interactive elements measure smaller than 44×44 CSS pixels:
- Top-nav links: 38px tall (`.top-nav a`, padding 8px 11px)
- `.icon-btn` (GitHub link): 33×34
- `.search-trigger`: height 32
- Filter chips: 11px font, around 28px tall

Not strictly an AA failure (target size is AAA in WCAG 2.1, AA in WCAG 2.2 at 24px which most meet), but mobile usability suffers. Bump nav-link padding to 10px vertical, icon button to 40×40.

### P2-2. `<input type="search">` with `aria-label` but no visible label

The three section search inputs (`#integSearch`, `#cronSearch`, `#projSearch`) have `aria-label` and the placeholder doubles as the visual label. Acceptable per SC 3.3.2 with `aria-label` present, but adding a hover/focus visible label is more accessible. Low priority.

### P2-3. `<div class="proj-item" tabindex="0">` with no `role` (SC 4.1.2)

Project items in the grid have `tabindex="0"` (making them focusable) but no `role="button"` and no keyboard handler for Enter/Space. They appear focusable but are not actionable from keyboard, which is confusing.

**Selector (line 1589):**
```html
<div class="proj-item" data-name="…" data-detail="…" tabindex="0"></div>
```
**Fix:** Either add `role="button"` plus a keydown handler for Enter/Space, or remove `tabindex="0"` if these are non-interactive.

### P2-4. Section anchors do not move focus (SC 2.4.3 Focus Order)

Clicking nav links (`<a href="#flow">`) scrolls but does not move keyboard focus into the target section. Screen-reader users tabbing after a nav-link activation jump back to top. Add `tabindex="-1"` to each `<section id="…">` and call `target.focus()` in the smooth-scroll handler.

### P2-5. Console scrollback is decorative (`aria-hidden="true"`)

Verified correct.

### P2-6. Pulsing LED inside `.dataflow-title` and `.live-pill`

Decorative. Wrapped in title text. Already disabled under `prefers-reduced-motion: reduce`. No issue.

## P3 polish (AAA niceties)

- `prefers-contrast: more` not honored. Consider a high-contrast variant that pushes `--mc-text-2` and `--mc-text-3` to 100% white.
- `prefers-color-scheme: light` is not handled. The site is dark-only. A light variant would help users with light sensitivity inverted.
- `.brand-name small` 9.5px is below comfortable reading size. Bump to 10.5 or 11px.
- Pulsing animations (`.live-pill .led`, `.df-core-pulse`) are infinite. Already disabled under `prefers-reduced-motion: reduce`. AAA SC 2.3.3 would avoid them entirely, but unnecessary for AA.
- `stat-num` 30px, `font-weight: 800` qualifies as "large" (3:1 threshold) and passes 16.47:1. Fine.

## Recommended fix order (highest impact first)

1. Add `:focus-visible` ring + skip link + `<main>` wrapper. One CSS block plus about 5 lines of HTML. Fixes 3 P0s.
2. Strip `role="tablist"` from `#integFilters`/`#cronFilters`/`#projFilters` and switch active state to `aria-pressed`. Fixes axe critical plus active-state P1.
3. Wire command-palette focus management (auto-focus input on open, return to trigger on close, `aria-expanded` toggle, `aria-label` on input). Fixes 2 P1s.
4. Footer `h4` to `h3`. One-character edit per heading.
5. Darken `.integ-type[data-type="CRM"]` color and raise `--mc-text-3` alpha. Fixes 5 contrast issues.

After steps 1 through 5, the page should pass WCAG 2.1 AA cleanly (Lighthouse 100, axe 0 violations).
